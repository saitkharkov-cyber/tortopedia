## 3. Prev / Next navigation

Восстановлена и автоматизирована нижняя навигация между связанными статьями.

### Новый источник данных

`src/_data/postNavigation.json`

В нём задаются тематические цепочки отдельно для RU и UA.

Текущая RU-цепочка:

1. `/kak-rabotat-s-mastikoi-dlya-torta/`
2. `/kak-hranit-mastiku-dlya-torta/`
3. `/kak-hranit-figurki-iz-mastiki/`
4. `/kak-sushit-figurki-iz-mastiki/`

UA-цепочка является зеркальной.

### Реализация

В `eleventy.config.cjs` добавлен фильтр:

`postNavigationFor`

Он:

- находит текущую страницу в тематической цепочке;
- определяет предыдущую и следующую страницу;
- получает title непосредственно из данных соседней страницы;
- возвращает URL + title в layout.

Обновлены:

- `src/_includes/layouts/article.njk`
- `src/_includes/layouts/article-uk.njk`

Для страниц из `postNavigation.json` навигация строится автоматически.

Старые ручные поля:

- `prev_url`
- `prev_title`
- `next_url`
- `next_title`

сохранены как fallback для старых статей, ещё не перенесённых в централизованную схему.

У 8 новых страниц (4 RU + 4 UA) ручные prev/next поля удалены после проверки автоматической навигации.

### Принцип

Prev/next строится не по дате публикации, а по смысловой последовательности материалов.

При добавлении новой статьи её следует включать в `postNavigation.json` только в том случае, если для неё есть логичное место в тематической цепочке.

## 4. Текущая структура перелинковки

Используется гибридная схема:

- contextual article-to-article links;
- pillar -> child;
- child -> related child;
- категории;

- prev/next thematic navigation.

Цель — не строить формальную звезду или кольцо, а создавать тематические кластеры с естественными переходами.

## 7. Важная техническая инфраструктура

### Последние статьи

В `eleventy.config.cjs` используются коллекции:

- `recentRu`
- `recentUk`

Они автоматически выбирают опубликованные материалы по `lang`, сортируют по `published` и выводят последние 6 статей.

Используются в:

- sidebar RU/UA;
- блоке новых статей на главной RU/UA.

Ручное обновление списка последних статей при публикации нового материала не требуется.

### Главная страница

На RU и UA главных используется автоматический блок последних материалов.

Старый статический блок популярных рецептов удалён, чтобы не дублировать по смыслу сетку новых статей.

### Sitemap

При публикации новой статьи необходимо проверить:

- XML sitemap;
- HTML sitemap RU;
- HTML sitemap UA.

### Публикация

Рабочая схема:

`src/ -> Eleventy -> _site-pilot/ -> publish.ps1 -> production HTML в корне -> GitHub main -> Cloudflare Pages`

Фактическое состояние Git всегда имеет приоритет над документацией.

## 8. Правила дальнейшей работы

- Редактировать исходники в `src/`.
- После изменений: `npm run build`.
- Затем: `.\publish.ps1`.
- Проверять `git diff --check`.
- Проверять diff перед commit.
- Не делать commit/push без отдельного подтверждения.
- RU и UA всегда проверять отдельно.
- Не добавлять внутренние ссылки только ради количества.
- Для новых тематических статей проверять необходимость добавления в `src/_data/postNavigation.json`.
