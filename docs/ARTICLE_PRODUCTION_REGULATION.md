# ARTICLE PRODUCTION REGULATION

## Назначение

Этот документ задаёт обязательный порядок подготовки, сборки, публикации и проверки каждой новой статьи Tortopedia.

Главная цель — убрать плавающую последовательность действий и исключить пропуски обязательных этапов.

Творческая свобода допускается внутри текста, структуры материала и визуальной подачи, но сам производственный процесс статьи должен идти по регламенту.

---

## Главное правило

Нельзя переходить к следующему этапу, пока обязательные пункты текущего этапа не выполнены.

Нельзя считать статью готовой только потому, что написан текст.

Статья считается завершённой только после:

- подготовки RU-версии;
- подготовки UA-версии;
- подготовки и вставки изображений;
- проверки навигации;
- проверки карт сайта;
- сборки;
- публикации;
- проверки production;
- commit/push.

---

## Этапы производства статьи

### 1. Выбор темы

- [ ] Проверить `docs/CONTENT_PLAN.md`
- [ ] Проверить `docs/CONTENT_MAP.md`
- [ ] Проверить существующие статьи сайта
- [ ] Проверить риск каннибализации
- [ ] Определить самостоятельный поисковый интент
- [ ] При необходимости проверить старое семантическое ядро / Keyword Planner

Результат этапа: утверждённая тема и понимание, зачем нужна отдельная статья.

---

### 2. Идентификатор статьи

- [ ] Проверить максимальный глобальный `post_id`
- [ ] Убедиться, что нового ID ещё нет
- [ ] Новый `post_id = max + 1`
- [ ] Один и тот же `post_id` используется для RU и UA версии одной статьи

---

### 3. План статьи

- [ ] Сформировать структуру H1/H2/H3
- [ ] Проверить, что структура отвечает интенту
- [ ] Убрать блоки, которые создают пересечение с другими статьями
- [ ] Определить внутренние ссылки на существующие материалы
- [ ] До написания текста определить примерные места будущих иллюстраций

---

### 4. Фактчек

- [ ] Проверить спорные и технические утверждения
- [ ] Использовать надёжные источники
- [ ] Не переносить названия внешних источников в текст статьи без необходимости
- [ ] Не придумывать универсальные нормы там, где они зависят от продукта, состава или условий

---

### 5. RU-версия

- [ ] Создать source-файл в `src/.../index.html`
- [ ] Добавить front matter
- [ ] Указать canonical
- [ ] Указать `hreflang_ru`
- [ ] Указать `hreflang_uk`
- [ ] Указать `lang_switch_url`
- [ ] Указать `post_id`
- [ ] Указать `published`
- [ ] Указать `category_slug`
- [ ] Указать `prev_url`
- [ ] Указать `prev_title`
- [ ] Написать текст по `docs/TORTOPEDIA_CONTENT_STYLE_GUIDE.md`
- [ ] Добавить внутренние ссылки
- [ ] Указать `image_src`, `image_width`, `image_height`, `image_alt` после выбора hero

---

### 6. UA-версия

UA-версия обязательна для каждой новой статьи.

Нельзя откладывать её "на потом".

- [ ] Создать `src/uk/.../index.html`
- [ ] Использовать тот же `post_id`
- [ ] Указать UA canonical
- [ ] Указать RU/UA hreflang
- [ ] Указать обратный `lang_switch_url`
- [ ] Перевести title
- [ ] Перевести SEO title
- [ ] Перевести description
- [ ] Перевести H1 и весь текст
- [ ] Проверить внутренние ссылки на UA-страницы
- [ ] Проверить `prev_url` и `prev_title`
- [ ] Проверить UA `image_alt`

---

### 7. План изображений и подготовка промптов

Изображения нельзя генерировать хаотично по ходу статьи.

До генерации сначала определить, сколько изображений требуется статье и какие смысловые места текста желательно проиллюстрировать.

Для каждой статьи заранее определить:

- [ ] Hero image
- [ ] Количество inline-изображений
- [ ] Примерное место каждого изображения в статье
- [ ] Соотношение сторон
- [ ] Общий визуальный стиль
- [ ] Нужно ли сохранять визуальную преемственность между изображениями

Ориентир:

- короткая статья: hero + 1–2 inline;
- средняя статья: hero + 2–3 inline;
- длинный практический материал: hero + 3–5 inline.

Количество изображений — ориентир, а не жёсткая норма. Оно определяется длиной статьи и тем, действительно ли визуал помогает читателю.

После определения набора изображений для каждого визуала подготовить промпты.

#### Hero image

Для главного изображения статьи подготовить:

- [ ] 2 разных промпта для ChatGPT
- [ ] 2 разных промпта для Gemini

Итого: **4 промпта на hero image**.

Промпты должны предлагать разные визуальные решения, а не быть простыми перефразировками одного варианта.

Главное изображение особенно важно для страницы статьи, категорий, главной страницы и социальных сетей, поэтому для него обязательно получить несколько разных подходов.

#### Inline images

Для каждого внутреннего изображения подготовить:

- [ ] 1 промпт для ChatGPT
- [ ] 1 промпт для Gemini

Итого: **2 промпта на каждое inline-изображение**.

Промпты могут отличаться:

- композицией;
- ракурсом;
- крупностью плана;
- способом показать действие или проблему;
- степенью бытовой / редакционной подачи.

При этом оба варианта должны решать одну и ту же задачу внутри статьи.

Перед генерацией показать пользователю подготовленные промпты.

Генерацию не начинать до согласования промптов пользователем.

---

### 8. Генерация и подготовка изображений

Для каждого изображения:

- [ ] Промпты согласованы
- [ ] Изображения сгенерированы
- [ ] Получены варианты по согласованным промптам ChatGPT / Gemini
- [ ] Пользователь выбрал итоговое изображение
- [ ] При необходимости выполнена корректировка
- [ ] Подготовлен WebP
- [ ] Сделаны необходимые размеры
- [ ] Проверено имя файла
- [ ] Подготовлен alt
- [ ] Файлы скопированы в `wp-content/uploads/YYYY/MM/`
- [ ] Изображение вставлено в RU
- [ ] Изображение вставлено в UA

---

### 9. Навигация между статьями

Для новой статьи:

- [ ] Добавить `prev_url`
- [ ] Добавить `prev_title`

Для предыдущей статьи:

- [ ] Добавить reciprocal `next_url`
- [ ] Добавить reciprocal `next_title`

Проверить отдельно RU и UA.

---

### 10. Категории

Category listing формируется автоматически через Eleventy.

Не добавлять карточку новой статьи вручную, если автоматическая система работает.

После build проверить:

- [ ] RU category
- [ ] UA category
- [ ] `post_id`
- [ ] title
- [ ] URL
- [ ] изображение

---

### 11. HTML Sitemap

HTML Sitemap пока обновляется вручную.

Обязательно добавить статью:

- [ ] `src/html-sitemap/index.html`
- [ ] `src/uk/html-sitemap/index.html`

После build проверить обе generated-версии.

---

### 12. llms.txt

`src/llms.njk` сейчас ведётся вручную.

- [ ] Решить, должна ли статья быть добавлена в `llms.txt`
- [ ] Если да — добавить запись
- [ ] Проверить generated `llms.txt`

Не считать `llms.txt` полной картой сайта.

---

### 13. XML Sitemap

`sitemap.xml` формируется автоматически.

После build:

- [ ] Проверить RU URL
- [ ] Проверить UA URL

Не добавлять записи вручную, если автоматическая генерация работает.

---

### 14. Build

Запустить:

`npm run build -- --quiet`

Проверить:

- [ ] build завершён без ошибок
- [ ] количество файлов ожидаемое
- [ ] нет unresolved template markers
- [ ] новая RU страница создана
- [ ] новая UA страница создана
- [ ] category listing обновлён
- [ ] HTML sitemap обновлён
- [ ] sitemap.xml обновлён

---

### 15. Проверка `_site-pilot`

Для RU и UA проверить:

- [ ] canonical
- [ ] hreflang
- [ ] H1
- [ ] `post_id`
- [ ] `prev`
- [ ] `next`, если применимо
- [ ] изображения
- [ ] alt
- [ ] language switch
- [ ] category card
- [ ] HTML sitemap
- [ ] XML sitemap

---

### 16. Publish

Запустить:

`.\publish.ps1`

Проверить:

- [ ] количество copied/unchanged выглядит логично
- [ ] `Stale production HTML: 0`
- [ ] нет ошибок
- [ ] `git diff --check` чистый

---

### 17. Git review

До staging:

- [ ] посмотреть `git status --short`
- [ ] убедиться, что нет случайных файлов
- [ ] не включать `docs/HANDOFF.md`, если сессия продолжается

После staging:

- [ ] `git diff --cached --check`
- [ ] убедиться, что staged только нужные изменения

Commit/push делать только после явного подтверждения пользователя.

---

### 18. Production check

После push проверить RU и UA в production.

Для обеих страниц:

- [ ] HTTP 200
- [ ] canonical
- [ ] hreflang
- [ ] H1
- [ ] `post_id`
- [ ] language switch
- [ ] изображения
- [ ] prev/next
- [ ] RU/UA category listing
- [ ] HTML Sitemap
- [ ] XML Sitemap

Отдельно проверить reciprocal `next` на предыдущей статье RU и UA.

---

### 19. Завершение статьи

Статья считается полностью опубликованной только когда:

- [ ] RU работает
- [ ] UA работает
- [ ] изображения на месте
- [ ] category listing обновлён
- [ ] HTML sitemap обновлён
- [ ] sitemap.xml обновлён
- [ ] prev/next работает
- [ ] production проверен
- [ ] commit/push выполнен

---

## Запрещённые сокращения процесса

Нельзя:

- забывать UA-версию;
- генерировать изображения до согласования промптов;
- считать hero единственным обязательным изображением для длинной статьи;
- забывать reciprocal `next`;
- забывать HTML Sitemap;
- вручную править production HTML вместо `src/`;
- вручную добавлять category card, если она автоматическая;
- вручную редактировать XML sitemap, если он генерируется;
- делать commit/push без проверки staged diff;
- трогать `docs/HANDOFF.md`, пока пользователь явно не завершает сессию.

---

## Рабочий принцип ChatGPT

При сопровождении новой статьи ChatGPT обязан вести процесс строго сверху вниз по этому документу.

Если этап уже выполнен, его можно отметить и перейти дальше.

Если обязательный этап пропущен, нужно вернуться к нему до публикации.

При команде пользователя `++`, `+++` или `++++` считать текущий шаг выполненным и дать только следующий шаг.
