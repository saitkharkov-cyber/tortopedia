# Tortopedia — DECISIONS

Здесь фиксируются решения, которые важно не пересматривать без новой причины и проверки.

## D-001. Сайт остаётся статическим

Tortopedia не восстанавливается как работающий WordPress.

Старый WordPress используется только как источник экспортированного контента и ресурсов.

Причина: текущая задача — сохранить и развивать существующий сайт без необходимости поддерживать устаревший WP-стек.

## D-002. Публикация через Cloudflare Pages

Production размещён на Cloudflare Pages и связан с GitHub.

Ветка публикации:

```text
main
```

Схема публикации:

```text
локальная рабочая копия → локальная сборка → проверка → GitHub main → Cloudflare Pages → tortopedia.in.ua
```

Cloudflare Pages автоматически публикует содержимое после push в `main`.

Cloudflare не используется как место скрытой Eleventy-сборки.

## D-003. Общий CSS вынесен в `/tortopedia.css`

Дублирующийся inline CSS не должен снова копироваться во все HTML-страницы.

## D-004. UTF-8 задаётся явно

Каждая HTML-страница должна иметь корректный:

```html
<meta charset="UTF-8">
```

в `<head>`.

Причина: без явного charset браузер на части страниц неверно определял кодировку.

## D-005. Контентные изображения — WebP

JPG/JPEG и часть PNG из `wp-content/uploads` были преобразованы в WebP после проверки ссылок.

Не применять это решение автоматически к theme/service PNG.

Прозрачность, UI-графика, favicon и служебные файлы требуют отдельной проверки.

## D-006. LightSlider только там, где реально используется

LightSlider нужен только на страницах, где существует реальный слайдер.

Исторически он используется на двух главных:

```text
/index.html
/uk/index.html
```

На внутренних страницах библиотека не должна подключаться без подтверждённого реального использования.

## D-007. FlexSlider удалён

Реальных FlexSlider-элементов в статическом сайте не найдено.

Подключение `jquery.flexslider.js` и мёртвые вызовы из `custom.js` удалены.

Возвращать библиотеку только после подтверждения нового реального использования.

## D-008. jQuery сохраняется для старых зависимостей

Старые theme/plugin-скрипты зависят от jQuery.

Поэтому:

```text
/wp-includes/js/jquery/jquery.js
```

должен загружаться до зависимых скриптов на страницах, где эти зависимости используются.

Текущая контрольная Eleventy-сборка содержит:

```text
52 HTML-файла
```

Количество уменьшилось с 54 до 52 после удаления дублирующей пагинации категории `vse-o-mastike/page/2/` в RU и UA версиях.

При дальнейшем изменении структуры не считать число 52 вечной константой без проверки фактической сборки.

## D-009. Не удалять старые ресурсы по предположению

Tortopedia — восстановленный статический сайт со значительным количеством исторических зависимостей.

Любое массовое удаление выполняется только после поиска фактических ссылок в HTML/CSS/JS и проверки результата.

Имя файла, происхождение из WordPress или визуальная «старость» сами по себе не являются достаточной причиной для удаления.

## D-010. Абсолютные root-relative пути допустимы

Для общих ресурсов допустимы пути вида:

```text
/wp-includes/...
/tortopedia.css
```

Это снижает риск ошибок на страницах с разной глубиной вложенности.

## D-011. Eleventy используется как локальный генератор

Миграция на Eleventy выполнена.

Источник истины для редактируемого контента и шаблонов находится в:

```text
src\
```

Текущая схема:

```text
src + layouts/partials
→ npm run build
→ _site-pilot
→ publish.ps1
→ production HTML
→ GitHub main
→ Cloudflare Pages
```

Текущая конфигурация Eleventy:

```text
input:  src
output: _site-pilot
```

Production-сборка не должна зависеть от скрытой генерации на стороне Cloudflare.

Перед публикацией необходимо иметь возможность локально проверить:

- итоговый HTML;
- SEO-разметку;
- URL;
- diff;
- неожиданные изменения.

`_site-pilot/` является промежуточным output и не является рабочим источником контента.

## D-012. Responsive images используют `w`-дескрипторы и `sizes`

Для одинакового изображения разных физических размеров использовать:

```html
srcset
sizes
```

с реальными `w`-дескрипторами.

Для типичного контентного изображения статьи ориентир:

```text
480w / 865w / 1200w / master
```

Конкретный набор зависит от:

- фактической ширины изображения в макете;
- разрешения исходника;
- визуального качества;
- смысла увеличения размера.

Не использовать схему `1x / 2x / 3x` как основной стандарт для обычных responsive images.

Пример типового `sizes`:

```html
sizes="(max-width: 865px) 100vw, 865px"
```

`<picture>` использовать только там, где действительно нужен альтернативный источник:

- отдельный мобильный кроп;
- другой формат;
- другая композиция;
- иное содержимое изображения.

Не заменять все `<img>` на `<picture>` механически.

Для новых и переработанных изображений сохранять:

- корректные `width` и `height`;
- осмысленный `alt`;
- `loading="lazy"` для изображений вне первого экрана;
- при необходимости `decoding="async"`.

Не делать искусственный апскейл изображения без практической пользы.

## D-013. Исходники важнее production-копий

Если страница управляется через Eleventy, содержательные изменения в первую очередь вносятся в:

```text
src\
```

или соответствующие layouts/partials.

Production HTML не должен становиться самостоятельным вторым источником истины.

После изменения исходников выполняется сборка и проверяется результат.

## D-014. Документация хранится в основном репозитории

Рабочая документация проекта находится в:

```text
D:\Git\tortopedia\docs
```

и отслеживается тем же Git, что и сайт.

Отдельный рабочий Git-репозиторий для документации не используется.

Документация находится вне `src/`, поэтому при текущей конфигурации Eleventy не попадает в production-сборку сайта.

Единственная точка входа в новую рабочую сессию:

```text
docs/START_SESSION.md
```

## D-015. Не делать массовую косметическую очистку без практической пользы

Tortopedia содержит заметное наследие старого WordPress.

Не нужно стремиться сделать код «идеально чистым» ради самой чистоты.

Приоритет:

```text
SEO → контент → UX → технические проблемы, реально влияющие на сайт
```

Применяется принцип разумного 80/20.

Рефакторинг и очистка допустимы тогда, когда дают понятную практическую пользу или уменьшают реальный риск.
