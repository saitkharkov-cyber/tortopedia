# Tortopedia — DECISIONS

Здесь фиксируются решения, которые важно не пересматривать без новой причины и проверки.

## D-001. Сайт остаётся статическим

Текущий Tortopedia не восстанавливается как работающий WordPress. Старый WordPress используется только как источник экспортированного контента и ресурсов.

Причина: текущая задача — сохранить и развивать существующий сайт без необходимости поддерживать устаревший WP-стек.

## D-002. Публикация через Cloudflare Pages

Production размещён на Cloudflare Pages и связан с GitHub.

Ветка публикации: `main`.

Схема:

`локальная рабочая копия → GitHub main → Cloudflare Pages → tortopedia.in.ua`

Cloudflare Pages автоматически публикует содержимое после push в `main`.

## D-003. Общий CSS вынесен в `/tortopedia.css`

Дублирующийся inline CSS не должен снова копироваться во все HTML-страницы.

## D-004. UTF-8 задаётся явно

Каждая HTML-страница должна иметь корректный `<meta charset="UTF-8">` в `<head>`.

Причина: без явного charset браузер на части страниц неверно определял кодировку.

## D-005. Контентные изображения — WebP

JPG/JPEG и часть PNG из `wp-content/uploads` были преобразованы в WebP после проверки ссылок.

Не применять это решение автоматически к theme/service PNG: прозрачность, UI-графика и служебные файлы требуют отдельной проверки.

## D-006. LightSlider только на двух главных

LightSlider нужен для реального `#slider` на:
- `/index.html`;
- `/uk/index.html`.

На внутренних страницах библиотека не должна подключаться без появления реального элемента, которому она нужна.

## D-007. FlexSlider удалён

Реальных FlexSlider-элементов в статическом HTML не найдено. Подключение `jquery.flexslider.js` и мёртвые вызовы из `custom.js` удалены.

Возвращать библиотеку только после подтверждения нового реального использования.

## D-008. jQuery должен быть на всех HTML-страницах

Старые theme/plugin-скрипты зависят от jQuery. Поэтому `/wp-includes/js/jquery/jquery.js` должен загружаться до них на каждой HTML-странице.

Проверенное количество HTML-страниц: 54.

## D-009. Не удалять старые ресурсы по предположению

Tortopedia — статический экспорт старой CMS с историческими зависимостями. Любое массовое удаление делается только после поиска фактических ссылок в HTML/CSS/JS и проверки сайта.

## D-010. Абсолютные root-relative пути допустимы

Для общих ресурсов допустимы пути вида `/wp-includes/...` и `/tortopedia.css`. Это снижает риск ошибок с разной глубиной вложенности страниц.

## D-011. Будущий генератор HTML собирается локально

Если для дальнейшего развития сайта будет внедрён Eleventy (11ty) или другой static site generator, production-сборка не должна зависеть от скрытой генерации на стороне Cloudflare.

Рабочая схема должна быть такой:

`исходники/шаблоны → локальная сборка → проверка готового HTML → GitHub → Cloudflare Pages`.

В GitHub должен попадать итоговый проверенный статический HTML. Это сохраняет полный контроль над фактическим HTML, SEO-разметкой, URL и diff перед публикацией.

Переход на 11ty не является ближайшей обязательной задачей. Сначала нужно стабилизировать SEO существующего статического сайта.

## D-012. Responsive images: 1x / 2x / 3x

Для контентных изображений нужно постепенно перейти к responsive images.

Если изображение одинаковое по композиции и отличается только физическим размером, использовать `img` с `srcset` и `sizes`. Минимально предусматривать варианты для плотности/размеров экранов 1x / 2x / 3x. Базовый ориентир для типового контентного изображения: `480w / 960w / 1440w`, если исходное изображение имеет достаточное разрешение.

`<picture>` использовать только там, где требуется альтернативный источник: отдельный мобильный кроп, другой формат или другая композиция.

Не заменять все `<img>` на `<picture>` механически.

Для новых и переработанных изображений сохранять:
- корректные `width` и `height` для уменьшения CLS;
- осмысленный `alt`;
- `loading="lazy"` для изображений вне первого экрана;
- при необходимости `decoding="async"`.

Размеры и наборы `srcset` должны подбираться по фактической ширине изображения в макете, а не только по фиксированному шаблону.
