## Глоссарий терминов

Цель глоссария — не SEO само по себе, а помощь новичку в понимании материалов Tortopedia.

Если читатель встречает незнакомый термин вроде `топпер`, `КМЦ`, `молд`, `вайнер`, `айсинг` и т. п., он должен быстро понять его значение и продолжить чтение без необходимости искать объяснение на других сайтах.

Глоссарий должен соответствовать общему позиционированию Tortopedia:

> практический справочник по домашнему декору тортов для человека без профессионального кондитерского опыта.

### Базовая структура

Предусмотреть отдельную страницу-глоссарий со списком основных терминов.

Для каждого термина использовать простое объяснение без профессионального перегруза:

1. Что это.
2. Для чего используется.
3. Где встречается в работе с тортами.
4. При необходимости — чем отличается от похожих понятий.
5. Иллюстрация, если термин сложно понять только по тексту.

### Связь со статьями

Термины должны быть связаны с основными материалами Tortopedia внутренними ссылками.

Если в статье появляется понятие, которое начинающий читатель может не знать, желательно дать возможность быстро перейти к его объяснению.

При этом не превращать статьи в энциклопедию и не ставить ссылки на очевидные общеупотребительные слова.

### Отдельные страницы терминов

Не создавать отдельную страницу для каждого слова только ради количества страниц или SEO.

Короткие и простые определения можно оставить внутри общей страницы глоссария.

Для важных терминов, которые требуют более подробного объяснения, допускаются:

- отдельные короткие страницы;
- расширенные карточки;
- ссылки на существующие полноценные статьи Tortopedia.

Отдельная страница оправдана, если одного короткого определения уже недостаточно для понимания термина.

### Первый набор терминов

Начать примерно с 20–30 базовых понятий, которые чаще всего встречаются в материалах Tortopedia.

Предварительный список:

- мастика;
- мастика для обтяжки;

- пищевой краситель;
- гелевый краситель;

Список не считать окончательным. Пополнять глоссарий по мере появления новых статей и терминов, которые требуют пояснения новичку.

### Принцип развития

Глоссарий должен развиваться вслед за основным контентом, а не отдельно от него.

При подготовке каждой новой статьи проверять:

- появились ли новые профессиональные термины;
- понятны ли они человеку без кондитерского опыта;
- есть ли термин уже в глоссарии;
- нужно ли добавить определение или внутреннюю ссылку.

Глоссарий должен уменьшать порог входа в материалы Tortopedia, а не становиться самостоятельным SEO-каталогом терминов.

### Интерактивные подсказки в статьях

Принято решение дополнить глоссарий контекстными всплывающими подсказками непосредственно внутри статей.

Логика:

- при первом появлении потенциально непонятного термина в статье читатель может открыть короткое пояснение;
- на десктопе подсказка должна работать по наведению и/или клику;
- на мобильных устройствах — по тапу;
- подсказка содержит короткое определение на 1–3 предложения;
- для сложных терминов внутри подсказки может быть ссылка `Подробнее` на глоссарий, расширенную карточку или отдельный материал;
- повторные употребления того же термина в одной статье оставлять обычным текстом, чтобы не перегружать страницу.

Определения не дублировать вручную в каждой статье.

Создать единый централизованный источник терминов с RU/UA-версиями определений. Статьи должны обращаться к нему по идентификатору термина, например:

```text
topper
kmc
mold
veiner
```

Это позволит:

- исправлять определение в одном месте;
- автоматически использовать одинаковое объяснение во всех статьях;
- поддерживать симметрию RU/UA;
- в дальнейшем автоматически формировать из тех же данных страницу общего глоссария.

Важно: хинты должны помогать чтению, а не превращать текст в набор всплывающих элементов. Добавлять их только к действительно профессиональным или потенциально непонятным новичку терминам.

## HIGH — актуальный lastmod для страниц-агрегаторов

При публикации новой статьи автоматически обновлять `lastmod` тех страниц, содержимое которых реально изменилось:

- RU главная `/`;
- UA главная `/uk/`;
- RU категория, в которой опубликована статья;
- соответствующая UA-категория.

Правило:

- для главной использовать дату самой свежей статьи, которая фактически выводится в `recentRu` / `recentUk`;
- для категории использовать дату самой свежей опубликованной статьи, которая фактически входит в её `categoryArticlesFor`;
- учитывать `updated` статьи, если оно есть, иначе `published`;
- не использовать build date, filesystem mtime или искусственно текущую дату;
- реализовать централизованно в Eleventy / `src/sitemap.njk`.

Цель: sitemap должен отражать реальные содержательные изменения страниц, на которых появляются ссылки на новые материалы.

## Open Graph и social meta

Для корректных превью материалов Tortopedia в Facebook, мессенджерах и других соцсетях добавить централизованный social-meta слой в общий `head`.

Базовый набор Open Graph:

- `og:type` — для статей `article`, для обычных страниц соответствующий тип;
- `og:title` — брать из `seo_title` с fallback на `title`;
- `og:description` — брать из `seo_description`;
- `og:url` — брать из `canonical`;
- `og:image` — брать из hero/главного изображения материала;
- `og:site_name` — `Tortopedia`;
- `og:locale` — `ru_UA` / `uk_UA` в зависимости от языка;
- при наличии корректных данных добавлять `og:image:width` и `og:image:height`.

Также добавить Twitter/X Card на тех же данных:

- `twitter:card=summary_large_image`;
- `twitter:title`;
- `twitter:description`;
- `twitter:image`.

Архитектура:

- не прописывать social meta вручную в каждой статье;
- использовать общий partial/template;
- значения получать из front matter и уже существующих полей;
- RU/UA должны формироваться симметрично;
- предусмотреть безопасные fallback для страниц без hero-изображения.

После внедрения проверить несколько типов страниц:

- новая статья;
- старая статья;
- категория;
- главная RU;
- главная UA.

Отдельно проверить итоговые превью через инструменты Facebook/Meta после публикации.

Важно: Open Graph/social meta — отдельная задача от Schema.org/JSON-LD. JSON-LD предназначен в первую очередь для поисковых систем и structured data, а Open Graph — для корректного представления ссылок в соцсетях и мессенджерах.
