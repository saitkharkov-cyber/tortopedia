# START SESSION — Tortopedia

> **Единственная точка входа в рабочую сессию Tortopedia.**
>
> Новый чат всегда начинается с чтения этого файла.

---

## 1. Проект

Основной и единственный Git-репозиторий:

```text
D:\Git\tortopedia
```

Удалённый репозиторий:

```text
saitkharkov-cyber/tortopedia
```

Рабочая документация хранится внутри проекта:

```text
D:\Git\tortopedia\docs
```

Папка `docs/` является частью репозитория `tortopedia` и отслеживается тем же Git.

Она не должна попадать на сайт: Eleventy собирает сайт из `src/` в `_site-pilot/`, поэтому `docs/`, находящаяся вне `src/`, в production-сборку не входит.

---

## 2. Что читать в начале сессии

Всегда:

1. `START_SESSION.md`;
2. `CHATGPT_WORKFLOW_RULES.md`;
3. `CURRENT_SESSION_STATE.md`, если существует.

Дополнительно:

- `HANDOFF.md` — если продолжается работа из предыдущего чата или после длительной паузы;
- `TORTOPEDIA_CONTENT_STYLE_GUIDE.md` — при работе со статьями;
- `CONTENT_PLAN.md` — при выборе или планировании контента;
- `CHATGPT_WORKFLOW_REFERENCE.md` — по мере необходимости.

---

## 3. Стартовая проверка

Перед изменениями перейти в корень проекта:

```powershell
cd D:\Git\tortopedia
```

Проверить:

```powershell
git status --short
git log --oneline --decorate -5
```

Перед началом работы должны быть понятны:

- фактическое состояние файлов;
- состояние Git;
- текущая задача;
- один следующий шаг.

---

## 4. Приоритет источников

При расхождениях верить в таком порядке:

1. фактическим файлам;
2. Git;
3. подтверждённым решениям текущей сессии;
4. свежему `CURRENT_SESSION_STATE.md`;
5. актуальному `HANDOFF.md`;
6. остальной документации;
7. памяти и старым сообщениям.

---

## 5. Контроль текущей сессии

Во время длинной работы поддерживать актуальным:

```text
CURRENT_SESSION_STATE.md
```

После заметных этапов проверять:

> Если чат оборвётся прямо сейчас, этого файла достаточно, чтобы продолжить работу без догадок?

Если нет — предложить обновить его.

`HANDOFF.md` используется для передачи контекста следующему чату или после длительной паузы.

---

## 6. После восстановления контекста

Не строить длинный план без необходимости.

Определить один следующий шаг и продолжать работу согласно `CHATGPT_WORKFLOW_RULES.md`.
