## 3. Актуальная архитектура

Рабочая схема:

```text
src/
→ Eleventy
→ _site-pilot/
→ publish.ps1
→ production HTML в корне репозитория
→ GitHub main
→ Cloudflare Pages
→ tortopedia.in.ua
```

Eleventy:

```text
input: src
output: _site-pilot
```

Версия:

```text
Eleventy v3.1.6
```

Документация находится в:

```text
docs/
```

и не попадает в production, потому что находится вне `src/`.

Правило:

```text
редактировать source в src/
не редактировать production HTML вручную
```

После правок:

```powershell
npm run build
.\publish.ps1
```

Затем проверить diff и только после отдельного подтверждения делать commit/push.

## 6. Последние авторские правки

2026-09-16 Мария, автор сайта, просмотрела статью и дала положительный отзыв.

Она предложила добавить два практических блока.

### Защита от влаги

В RU и UA версии добавлено:

- полностью высохшие фигурки можно хранить в герметичном пластиковом контейнере;
- контейнер закрывать только после полного высыхания;
- для дополнительной защиты можно положить пакетик силикагеля, пригодного для использования рядом с пищевыми продуктами;
- силикагель не должен соприкасаться с фигурками;
- не рекомендуется просто складывать фигурки в полиэтиленовый пакет из-за риска конденсата.

### Тонкие трещины

Добавлен практический способ ремонта:

```text
маленький кусочек мастики
+
капля пищевого клея
→ пастообразная масса
→ аккуратно заполнить тонкую трещину
→ после высыхания сгладить
```

Отдельно пояснено, что глубокая трещина означает потерю прочности и простая маскировка её не восстанавливает.

## 9. Что не нужно повторять

Не возвращаться без причины к:

- миграции документации;
- отдельному `tortopedia-docs`;
- старой схеме вложенного Git;
- ручному редактированию production HTML;
- повторной отправке статьи про хранение фигурок в GSC;
- повторному исправлению footer whitespace;
- старому вопросу про `54 HTML`, если `publish.ps1` сам работает нормально.

Не менять `publish.ps1` только потому, что Eleventy сейчас пишет:

```text
Wrote 59 files
```

Защитный порог в скрипте — отдельная проверка и не обязан совпадать с текущим фактическим количеством файлов.

## 13. Стиль работы

Пользователь предпочитает:

- один следующий шаг за раз;
- короткие PowerShell-команды;
- PowerShell-команды в одну строку;
- не делать commit/push без явного подтверждения;
- не предлагать лишнюю архитектурную переделку;
- не расширять задачу без причины;
- при замене Markdown-документа давать полный файл целиком;
- если внутри Markdown есть тройные backticks, внешний блок оформлять четырьмя backticks.

`+++` означает:

```text
предыдущий предложенный шаг успешно выполнен
```

и разрешает перейти только к следующему шагу, а не автоматически выполнять все последующие действия.
