## 5. Sitemap

### XML

`src/sitemap.njk` генерирует XML sitemap автоматически.

Используется `lastmod`:

```text
updated -> published -> без lastmod
```

Не использовать build date или filesystem mtime.

Статья КМЦ автоматически попала в sitemap.xml.

### HTML

HTML sitemap пока статический.

При каждой новой статье нужно вручную проверить/обновить:

```text
src/html-sitemap/index.html
src/uk/html-sitemap/index.html
```

Для КМЦ это уже сделано и запушено commit `1f9dbef`.

## 6. Важное решение по следующему контенту

НЕ продолжать сейчас отдельным обзором:

```text
CMC / Tylose / Gum-Tex / трагакант / другие добавки
```

Причина: опубликованная статья КМЦ уже достаточно широко закрывает этот intent, и отдельный обзор рядом может создать каннибализацию.

Следующая тема должна расширять сайт новым поисковым интентом.

## 7. Главная задача следующей сессии

Не писать новую статью с ходу.

Сначала провести ревизию контентного плана и старой семантики.

Порядок:

1. изучить `docs/CONTENT_PLAN.md`;
2. поднять старое семантическое ядро Tortopedia;
3. сверить его с `docs/CONTENT_MAP.md`;
4. отметить уже закрытые запросы/кластеры;
5. выделить неохваченные самостоятельные кластеры;
6. проверить риск каннибализации;
7. только после этого актуализировать кандидатов через Keyword Planner и SERP;
8. выбрать следующий материал;
9. утвердить H1/slug/структуру;
10. только затем писать.

Важно: старое семантическое ядро — не вспомогательный материал, а одна из основных отправных точек выбора темы.

Точное местоположение файла/таблицы старого ядра в этом HANDOFF не зафиксировано — найти/уточнить в начале сессии, не придумывать заново.

## 10. Контентный стиль

Перед написанием следующей статьи обязательно перечитать:

```text
docs/TORTOPEDIA_CONTENT_STYLE_GUIDE.md
```

Рабочий стиль:

- 70–80% старого голоса Tortopedia;
- 20–30% новой практической структуры;
- спокойно, уверенно, по делу;
- не академично;
- не рекламно;
- не «стерильный AI»;
- короткие связные абзацы;
- конкретные действия;
- measurable specifics только при наличии источника;
- предупреждения и советы только там, где они реально помогают.

Перед новым материалом полезно перечитать 5–7 близких статей сайта.

## 11. Технические правила работы

Пользователь предпочитает:

- один следующий шаг за раз;
- `+++` = предыдущий шаг успешно выполнен, дать только следующий;
- PowerShell-команды одной строкой;
- `git add` одной строкой через `&&`;
- сначала проверить факты, затем менять;
- не делать scope creep;
- не commit/push без явного подтверждения;
- RU и UA проверять отдельно;
- перед commit смотреть diff;
- использовать `git diff --check`.

Публикация:

```text
npm run build
-> проверить _site-pilot
-> .\publish.ps1
-> git diff
-> git diff --check
-> git add
-> staged diff/stat
-> commit
-> проверить clean
-> push
```

## 14. Автоматизация категорий завершена 2026-09-19

Статические category listing частично переведены на автоматическое формирование через Eleventy.

Добавлен фильтр:

```text
categoryArticlesFor
```

Источник данных — front matter статьи:

```text
category_slug
lang
published
title
post_id
image_src
image_width
image_height
image_alt
```

Логика:

```text
category_slug + lang + published
-> фильтрация
-> сортировка published DESC
-> category template
-> автоматическая карточка
```

Используются:

```text
src/_includes/layouts/category.njk
src/_includes/layouts/category-uk.njk
```

H1 категории теперь формируется layout перед списком карточек.

Для `vse-o-mastike` ручные карточки новых материалов `901–903` удалены. КМЦ вручную в category source не добавлялась: она появилась автоматически.

После build проверены RU и UA:

```text
901 = 1
902 = 1
903 = 1
904 = 1
905 = 1
```

КМЦ использует единый ID:

```text
post_id: 905
post-905
```

Правило на будущее:

```text
один материал = один глобальный post_id для RU/UA
следующий ID = max + 1
```

Текущий максимум:

```text
1040
```

Следующий новый материал:

```text
1041
```

`publish.ps1` остаётся только этапом build/copy/check и не содержит контентной логики категорий.

Следующая задача после commit/push этой технической работы:

```text
CONTENT_PLAN.md
+ старое семантическое ядро
+ CONTENT_MAP.md
-> выбрать следующий самостоятельный поисковый кластер
```

Не уходить сейчас в отдельный обзор `CMC / Tylose / Gum-Tex / трагакант`: риск каннибализации со статьёй КМЦ.
