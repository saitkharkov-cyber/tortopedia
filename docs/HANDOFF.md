# Tortopedia — HANDOFF

Дата: 2026-09-01

## Статус

Production-сайт работает как статический HTML на Cloudflare Pages.

Основная ветка production: `main`.

Отдельная работа по Eleventy ведётся в ветке `pilot-11ty`; детали шаблонизатора вынесены в отдельный HANDOFF этой ветки и здесь не дублируются.

## Итоги работ по статической версии

### Восстановление и очистка

Старый WordPress-архив преобразован в обслуживаемый статический сайт. Проверены внутренние `href`/`src` и CSS `url(...)` ссылки.

Удалены ненужные обращения к WordPress runtime, включая старые `admin-ajax.php` и oEmbed/wp-json discovery-зависимости. Статические формы поиска оставлены как часть исходной разметки, но полноценного WordPress-поиска на статическом сайте нет.

### CSS и кодировка

Одинаковый большой inline CSS вынесен из HTML в `/tortopedia.css`.

На HTML-страницах добавлен UTF-8 charset.

Для `/wp-content/themes/bakes-and-cakes/images/banner-bg-top.png` добавлен preload.

### Favicon/manifest

Сотни версионных копий favicon/manifest-файлов были побайтно проверены, ссылки заменены на канонические файлы, дубликаты удалены.

### Изображения

Контентные JPG/JPEG и PNG из `uploads` преобразованы в WebP с проверкой наличия результата перед заменой ссылок.

Старые JPG/JPEG/PNG удалялись только после проверки отсутствия ссылок.

Следующий возможный этап по производительности — responsive images/srcset. Это отдельная задача, не срочная.

### Slider-библиотеки и jQuery

`lightslider.js` оставлен только на двух главных страницах, где реально есть слайдер: `/index.html` и `/uk/index.html`.

Неиспользуемый `jquery.flexslider.js` удалён, мёртвые вызовы FlexSlider очищены из `custom.js`.

После этого основной jQuery был добавлен на все HTML-страницы, где его не хватало. Ошибки `jQuery is not defined` на проверенных внутренних страницах исчезли.

## Итоги SEO-ревизии 2026-09-01

SEO-фундамент статической версии проверен и приведён в порядок без изменения успешной структуры URL.

Сделано:

- проверены и исправлены canonical для RU/UA;
- проверены hreflang-связки между RU и UA;
- подготовлен и проверен `sitemap.xml` на 54 URL;
- проверен `robots.txt`;
- sitemap отправлен в Google Search Console;
- внутренние ссылки приведены к нормальным статическим URL;
- проведён аудит внутренних ссылок, критических битых внутренних ссылок после правок не осталось;
- сохранена структура RU в корне и UA в `/uk/`;
- устранены/нормализованы старые варианты ссылок и дубли, которые могли вести на WordPress-подобные URL.

## Текущая архитектура

Production-схема:

`локальная рабочая копия → GitHub main → Cloudflare Pages → tortopedia.in.ua`

WordPress как движок не возвращается.

## Что важно не переделывать повторно

Не нужно снова массово чистить HTML только ради косметики. В проекте могут оставаться harmless WordPress-классы, старые технические имена и другие следы экспорта. Их не трогаем, если они:

- не видны пользователю;
- не ломают SEO;
- не создают ошибок;
- не влияют заметно на скорость.

Принцип дальше: 80/20 — только изменения с реальной пользой.

## Что осталось по `main`

Критической незавершённой уборки на конец дня не зафиксировано.

Дальше изменения в `main` делать только под конкретную задачу: SEO, производительность, ошибка, видимый мусор или функциональная проблема.

Responsive images/srcset можно делать позже отдельным этапом.

## Связанная ветка

Eleventy-пилот: `pilot-11ty`.

Для продолжения шаблонизации использовать отдельный HANDOFF в этой ветке.

## Правило продолжения

Перед массовыми заменами или удалением ресурсов:

1. определить фактические ссылки;
2. проверить обе языковые версии;
3. сделать локальный тест;
4. посмотреть `git diff --stat` и `git diff --check`;
5. только затем коммитить и публиковать.

Перед локальной работой после изменений, внесённых напрямую в GitHub:

```powershell
git pull origin main
```

Затем:

```powershell
git status
```
